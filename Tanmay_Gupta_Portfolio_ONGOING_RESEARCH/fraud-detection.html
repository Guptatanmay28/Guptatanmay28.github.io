01 — BUSINESS / RESEARCH QUESTION

Can transaction-level behavior identify potentially fraudulent activity?

The project investigates whether transaction type, transaction amount, account-balance behavior and engineered behavioral signals can distinguish fraudulent from legitimate transactions.

Decision focus: identify high-risk transactions while balancing fraud detection against false alerts.
02 — DATASET

PaySim transaction-level data

The project uses the PaySim synthetic financial transaction dataset. The working sample retains all fraud cases and samples legitimate transactions for a manageable, portfolio-ready analysis.

Important interpretation

04 — STATISTICAL ANALYSIS

Testing whether transaction type is associated with fraud

Chi-square test

Transaction type and fraud status were tested for association rather than relying only on visual patterns.

Result: statistically significant association in the working sample.

Why it matters

The statistical test supports treating transaction type as a useful predictive signal, while the model still evaluates it alongside balance and amount features.

08 — RISK DECISIONING

From probability to an operational decision

LOW RISK

Allow automatically when predicted fraud probability remains below the chosen review threshold.

REVIEW

Route borderline transactions for additional verification rather than immediately blocking them.

HIGH RISK

Flag transactions above the risk threshold for investigation.

The threshold should ultimately be chosen using business costs for missed fraud and false alerts, not model performance alone.

09 — LIMITATIONS

What this project does not claim

  • PaySim is synthetic rather than real banking data.
  • The working sample contains all fraud cases and a sampled legitimate population.
  • Very high model performance on this dataset should not be assumed to generalize to real financial systems.
  • Production deployment would require external validation, threshold calibration, drift monitoring and governance.
10 — CONCLUSION

A complete fraud-analytics workflow, not just a model.

The project combines exploratory analysis, statistical reasoning, feature engineering, classification, evaluation and risk decisioning. Random Forest materially outperformed the Logistic Regression baseline in the working sample, while the analysis highlights why model performance must still be interpreted in the context of synthetic data and operational costs.
